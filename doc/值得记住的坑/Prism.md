# Prism

现象：打开“更多”后，背景资源列数或位置发生变化。
原因：锁定背景滚动隐藏了垂直滚动条，可用宽度增加，触发了自适应网格重排。
做法：锁定滚动前保留滚动条占位；测试弹窗开关前后的背景坐标、宽度、滚动位置和焦点，不能只确认弹窗能关闭。

现象：审计“域名”栏目是否收齐时，漏掉了 2026 年 10 月上线的 lovie.me，以及同类只在中文社区传播的免费域名服务。
原因：调研把“已知的服务名清单”直接交给检索，做的是逐项核实，不是开放式发现；来源又以英文官方页和 GitHub 注册仓库为主，而这些新服务当时在英文来源里几乎查不到。
做法：判断“收齐没有”要分两步——先做开放式检索（中英文各一轮，带“最新 / 2026 / 开放申请”等时间词，并翻一遍持续更新的新服务聚合仓库），得到候选集；再逐项核实官方条款。已知清单只用于对照，不能当成检索范围。

现象：上一轮被判为“只有软文、无法核实，不收”的 DNSHE，下一轮单独访问它的官网就返回 200，FAQ 把免费后缀、180 天免费续期、可改 Nameserver 全写清了，官方仓库还在更新。
原因：“来源档次低”被当成了排除依据。软文里出现过只说明证据不足，不等于服务不存在；而且当时的抓取失败是多条目批量试探时的顺带结果，没有针对性重试。
做法：排除一个候选要给出“打了哪个具体地址、返回什么”，被 403/挑战页挡住就换原始存档或接口实测再判一次；只有二次仍拿不到一手页面才写“无法核实”，并把地址记下来，下次直接从这条查。

现象：三路检索结果到齐后写的汇总里出现了“My.ID / Wsinn / US.KG”三个服务和一堆具体数字（NS 枚数、已发放域名数、到期价格），但本轮检索记录里根本没有这些条目；同期还有五处资源描述被顺手加了“经 GitHub 申请”“须邮箱验证”“非营利组织可申请更多额度”“挂着付费方案”“能托管自己的域名”等条款细节。
原因：长会话压缩上下文后，“下一轮大概还能查到什么”的推断和“上一轮已经查到什么”的事实混在同一份记忆里，写总结时按叙事连贯性补内容，没有再区分有无出处；描述条目时同样凭印象补全，越具体越像真的。
做法：每个写进数据或文档的结论必须能指到本轮实际读过的页面（证据列填 URL 与核查日期），指不出来就当场重新抓取再落笔，不能靠“记得查过”；具体数字、流程步骤、条款要求属于最容易被编造的内容，优先级最高。已写入的存疑描述要逐条回查官方页并回滚，同时在检索记录文档里写明改了什么、依据是什么。

现象：只读了阿里云和腾讯云的活动页，就写下“这两家都不是按流量超额收费的路子”“月度流量包额度与超出后怎么处理页面没写”；下一轮读官方计费文档，两句全错——两家都是套餐含每月流量包、超额 0.8 元/GB，腾讯连逐档额度都公开在静态刊例表里。
原因：把促销页当成产品条款的完整来源。活动页只回答“首年多少钱、限购几台”，计费与退订规则在 `document/product/...` 的帮助文档树里，两处内容不同是常态而不是矛盾。
做法：判断“某条款有没有公布”要按文档层级查而不是看单个页面——先找该产品的“计费/退款/使用限制”专页再下结论；由促销页得到的推断必须标成推断，并在同一轮里安排回查。写错的句子要在检索记录里就地标注被哪一节推翻，不能悄悄改掉。

现象：京东云的定价文档 `curl` 回来 66 万字节，去标签后只剩 8.9 KB 的导航菜单；UCloud 三个文档页各 8301 字节、正文只有 28 个字符。差点据此写出“官网没有公开价格表”。
原因：这两个文档站是前端渲染，静态 HTML 里只有站点外壳与全站产品清单，正文要执行脚本才有；用 `curl` 读到的“内容长度”和页面真实内容无关。
做法：抓文档站后先看**去标签正文长度**，只有菜单量级就判定为 SPA，改用浏览器打开同一 URL 读 `document.body.innerText`；SPA 骨架不能当“官方没写”的证据。同一套办法要按站点切换——腾讯云文档是静态的，但不加 `--compressed` 会拿到 brotli 乱码。

现象：用 Bash 的 heredoc 写一段含中文和“¥”符号的 Python 脚本改数据文件，执行时报 `SyntaxError`，报错位置指向一个 `\xa5`；同一批中文参数在 Git Bash 里打印出来也是乱码。
原因：Windows 上的 shell 传参按本地代码页处理，多字节字符在传给 Python 前已被改写，字符串边界随之错乱。
做法：需要写含非 ASCII 字符的脚本或数据时，用文件写入工具落一个 UTF-8 的 `.py` 再执行，跑完删掉；读结果也走文件（`io.open(..., encoding="utf-8")` 写出、用文件阅读工具看），不要依赖终端回显中文。

现象：Amazon S3、CockroachDB、Wasabi 这些在聚合清单里被写成"有免费方案"的服务，读官方定价页拿到的却是 `Get up to $200 in credits for new customers`、`New Cloud organizations get a 30-day free trial with $400 in credit`、只有 30 天 / 14 天试用。
原因：清单把"新用户能白拿一阵"和"核心用途长期免费"记成同一栏；AWS 还把过去的 5 GB 免费存储整体换成赠金，官网改了、抄它的清单没改。
做法：判首页资格先问"赠金或试用到期后还能不能免费用"，只有额度过期、需绑卡才拿到的东西一律不算可持续免费；结论抄官方定价页里带 trial / credit / expires 的原句，这类服务进"付费优质平台"或"免费 · 待甄选"，不进首页。

现象：本轮 iagora 的定价页返回 HTTP 404、它的静态域名 DNS 直接解析失败，Stack 两次请求都是 HTTP 525，Better Auth 因为清单里少写一个连字符（`betterauth.com`）而 getaddrinfo failed——这些都是排名靠前、看起来最该收的候选。
原因：聚合清单没人复核，站点关停、改名、换域名都原样留着；转抄域名时连字符这类细节最容易被吞掉，而"打不开"被顺手当成"服务没了"。
做法：写进 `data/resources.json` 的每个 URL 落笔前先请求一次确认 200；失败要分清是拼写或域名问题（解析不到就按官方拼写重试）还是真停了（404/52x 再换存档确认一次），并把"打了哪个地址、返回什么"写进检索记录的"不收与打不开的地址"表，下次不必重撞。

现象：Auth0 免费档主卡写 `Free $0 / Up to 25,000 monthly active users / Includes 1 Custom Domain`，比 Clerk、Kinde 都宽；补读脚注才知道 `*credit card verification required for custom domains`，而 Essentials `$35 / month`、Professional `$240 / month` 两档各只含 `Up to 500 monthly active users`。同类还有 Cognito 要单独读 `the free tier pricing isn't available in the AWS GovCloud (US) Regions` 和 `There is no free tier for the Plus tier`。
原因：定价页把硬门槛放进脚注、地区说明和对照列，首页大字只印最宽的那个数字；各家计数口径还不一样（MAU、月留存用户 MRU、日活 DAU、应用数），付费档含的用量反而可能比免费档少。
做法：读定价页必须补齐"脚注 + 地区与前提条件 + 额度口径"三处再写简介，文档里抄原句；口径不同的服务不横向比大小，宁可在简介里写明它按什么单位计。

现象：AI 栏目一轮复核里有六条"当初写对了"的条目同时漂移——NotebookLM 改名 Gemini Notebook、riffusion.com 跳成 Google Flow Music、windsurf.com/pricing 跳进 devin.ai、labs.google/fx/tools/flow 独立成 flow.google.com、lumalabs.ai/dream-machine 变成 /app 且改讲创意智能体、elicit.org 换成 elicit.com。只测状态码全是 200，看上去一条都没坏。
原因：生成式 AI 产品改名、并站、换域名是以月为单位的常态，而 200 只说明旧地址还在做跳转，不说明条目名、入口和产品定位仍成立；站点标题与跳转终点不一致正是品牌已经换掉的信号。
做法：这类条目的复核要顺着**最终地址**走，把 `请求地址 → 跳转后地址 → 页面标题` 三段一起记进检索记录，条目的显示名与 URL 以跳转后的站点标题为准；旧地址仍能用时也在记录里注明它已跳转，避免下一轮把跳转当成"打不开"或把它当成两个不同产品重复收录。

现象：好几个官方定价页脚本抓回来只有标题或几百字导航（`feishu.cn/pricing` 正文 11 字、`zoom.us/pricing` 839 字、`meeting.tencent.com/buy.html` 1360 字），差点被写成"没读到免费档，不收或降级"；用浏览器打开同一个地址后，分别读到"免费版 ¥ 0 人/月 … 支持 100 用户"、"Workplace Basic Free … 40 minutes per meeting"、"免费版 1 个账号 ¥ 0 … 1G 云录制空间"。
原因：这些站点把版本对比表放在前端渲染组件里，静态 HTML 只留站点外壳与菜单，抓到的正文字数等于"组件有没有执行过"，与"官方有没有公布条款"无关；个别站点（`whereby.com/pricing`）连浏览器也只回 "Loading is taking long…"，所以取证方式本身必须被记录。
做法：判"有没有免费档"按三步走并留下每步结果——状态码 → 去标签正文字数 → 不足时用浏览器读 `document.body.innerText`；检索记录里注明这条结论是脚本抓的还是浏览器读的。浏览器也取不到就写"待核实"并记下地址，不许把"抓不到"写成"官方没写"。

现象：同一页面里"免费"有四种资格——腾讯会议把"问元宝 / 元宝纪要 / 智能录制"标成"限时免费"，Power Automate 写 "free for 30 days"，Basecamp 是 "Personal … free forever" 加商业档订阅，`jiandaoyun.com` 与 `jinshuju.net` 通篇只有"免费试用/申请试用"。
原因：中文站把促销期权益也写作"免费"，英文站把 free / free forever / free trial / no credit card 混排；按关键词命中做判断会把试用当成永久免费档，把到期收回的额度当成长期方案。
做法：抄证据原句时必须把"免费"前的限定词一起抄（免费版 / 免费档 / 永久免费 / 限时免费 / 免费试用 / 免费创建），首页资格只认"免费版、免费档、free forever、永久免费"这一类；带试用、天数、限时的一律进"付费优质平台"或"免费 · 待甄选"，并在简介里写明限时。

现象：复核网盘页时，`mega.io` 正文里三处免费容量都写成 `Sign up for !{freePlanStorage} free storage`，`jianguoyun.com/s/pricing` 的价格行是 `一年付：%s空间，额外立减160元`；同时未登录打开 `pan.xunlei.com`，界面上直接显示"已用小于10M / 2TB"。三个数字看着都能直接抄进条目。
原因：页面文本里的数字分三个层级——模板占位符（值由脚本或后端填充，抓到的是变量名）、未登录壳层的默认展示值（客户端先画好额度条再等接口回填）、成文条款里的数字（定价页、帮助中心的表与脚注）。前两级都不构成"官方公布的免费额度"。
做法：抄数字前先认层级：出现 `${...}`、`!{...}`、`%s`、`{{ }}` 就是没渲染，转去同页已渲染的区块（对比表、FAQ）或换浏览器再取；壳层默认值只当线索，不当条款。写进条目的额度必须来自定价/帮助页的成文句子，且把句子连同出处一起写进检索记录；迅雷云盘这类只有壳层数字的，降级到"免费 · 待甄选"并在简介里说明"具体条件要登录后确认"。

现象：`www.lanzou.com` 在本机三次尝试全部连接超时（urllib `WinError 10060`、浏览器 `ERR_CONNECTION_TIMED_OUT`），而同一团队的新产品线 `www.ilanzou.com` 用浏览器能正常打开并读到整套条款。差点把它当成"站点已死"删掉，或顺手把首页链接改成优享版域名。
原因：网盘类站点常因 CDN、备案或地区路由问题对特定网络不可达，"我这里打不开"测的是本机到站点的链路，不是服务状态；同厂商多域名又让"改一个能打开的域名"看起来无害，实际会把用户认知里的产品换掉（蓝奏云以"分享免登录"出名，优享版另有 100MB 免登录上限）。
做法：连接层失败（超时、DNS、TLS）与业务层失败（404、52x）分开记，写清"打了哪个地址、什么错"；仍要判存续就查搜索引擎收录的官方页文案与同厂商其他域名，只作辅证。原产品域名保持不变，另立条目收新产品线并各写自己的限制；条目里如实写"从海外访问需自行确认"，不悄悄换地址。

现象：`wetransfer.com` 首页正文 278 字只有 "Uh-oh... We couldn't load some important parts"，浏览器打开同一个地址 `innerText` 长度为 0，眼看要写成"免费方案无法核实"；它的帮助中心 `wetransfer.com/help-center/subscriptions/plan-limits`（页面标注 Updated 23 October 2026）却把条款写全了："Free — send up to 10 transfers (or 3 GB total) in any 30-day rolling window"、"On a free account, transfers expire after 3 days"、"no difference in upload or download speed between a Free account and a paid subscription"。而网上大量教程与旧资料仍说它"单次 2GB 不限量"。
原因：营销首页是重前端的应用，条款在帮助中心的静态文档树里；同一家公司的额度政策会改版（按次不限量 → 按 30 天滚动计量），首页抓不到不等于没公布，教程抄的还是旧规则。
做法：主站抓不到条款就先找它的 help center / docs / FAQ 子站，那里往往是同一厂商最完整的一手来源；取证时把页面自标的更新日期一起抄进记录，日后条款再变能看出是改版而不是读错。凡与流传甚广的旧说法冲突（"2GB 不限量"），以带日期的官方页为准并在文档里写明已改。

现象：给网盘页加"WebDAV"栏目时，中文聚合清单（`banzhuti.com`，自标"3年前更新"）把 Dropbox 写成支持 WebDAV，地址给的是 `https://dav.dropdav.com/`；同一张表还给 iCloud 写了 `http://icloud.com/en/webdav`。照这张表收，首页就会出现两家"其实没有官方 WebDAV"的服务。
原因：清单只回答"这个地址能不能连上"，不区分端点属于厂商还是第三方代理——dropdav.com 是靠账号密码转发的第三方网关，iCloud 那行在苹果任何文档里都不存在；域名看着像官方、写了服务器地址，就被当成同等级的证据。
做法：判"官方支持某协议"要同时拿到**厂商自有域名的端点**与**厂商文档里对该端点的说明**，两者缺一就降级为"待核实"；聚合清单只用于列候选名单，端点探测（如 PROPFIND 返回 401）只证明地址在线且要鉴权，不能单独当作支持声明。记录里写明这条资格来自哪个官方页面，而不是来自清单。

现象：坚果云的英文名是 Nutstore，于是按常规去 `nutstore.com` 取国际站资料，抓回来是 Grails 的域名出售页（"The domain name NUTSTORE.COM is available for sale"），`/webdav` 直接 RemoteDisconnected；但 `www.jianguoyun.com/s/pricing` 的英文页标题确实是 "Nutstore Free Personal Network Disk…"。
原因：品牌英文名与可注册域名是两件事，国内厂商的英文品牌常常没握同名 .com；"英文名 = 某个英文域名"这个推断在导航数据里会变成把用户带向停泊页或抢注站。
做法：条目的显示名（`nameEn`）从厂商自己页面的标题与正文取证，官网 URL 只认能返回产品内容的域名，两者分别核实、不互相推导；探到"看着像官方"的域名先看正文是不是产品页，出现 for sale / parking / domain hosting 之类字样就只当反向证据，并在检索记录写下该域名为何不能用。

现象：同一家 pCloud 出现两份互相打脸的一手来源——Zotero 论坛 2022-02-09 帖写 "From February 11th onwards, WebDAV will be only available for pCloud Premium users"，现行官方帮助页写 "These connection options are available for all pCloud plans, including free and paid accounts"。取前者它就不能上首页。
原因：论坛帖是当时生效的政策公告，帮助页是当前条款，两者时间不同并不矛盾；协议入口、免费档权益这类条款会被厂商反复收窄再放开，"哪个是官方"不能替代"哪个是现行"。
做法：以带日期或标称最新的官方页面作为现行结论，同时把反例线索（来源 + 日期 + 原句）一起写进检索记录，注明它已被推翻；下一轮复核先从这条反例查起，看条款有没有再改回去。首页资格只在"当前对免费账号开放"成立时才给。

现象：素材站的"免费"有两种完全不同的写法。Iconify 首页先说 "Almost all parts of the project use MIT license"，紧跟一句 "**This license does not apply to icons.** Icon sets use various open source licenses, see each icon set for details"；DaFont 更直接——"The licence mentioned above the download button is just an indication. Please look at the readme-files in the archives"。按整站授权写，就会出现"Font Awesome 整站随便商用""iconfont 全库免费商用"这种错。
原因：聚合型站点（图标集、字体、模型市场）只是入口，权利在上传者或各子集手里，页面顶部那个许可证讲的是**平台代码**而不是内容；工具型站点甚至主动声明自己的许可标签不可靠。

原因：Web Archive 对短时间批量请求限流，重试间隔按秒算根本不够；后台脚本在这种限流下既不出结果也不报错，看起来"还在干活"，实际只是在累积失败。
做法：Wayback 按分钟级退避、单站串行，绝不在一个后台脚本里循环等；改用在浏览器里打开 `web.archive.org/web/2026id_/<站点>` 让归档自己解析出具体快照，取到时间戳（本轮天地图为 **20261005062425**）后再用 urllib 单发一次 `id_` 原始页取正文，并把快照时间戳写进检索记录。后台脚本超过预期时长没有产出就停掉换路，不要留着它继续占位。

现象：中国境内站点本轮成批取不到正文——`tianditu.gov.cn`、`map.tianditu.gov.cn`、`data.stats.gov.cn` 返回 **418**"your request has been intercepted because it appears to be an attack"与 **403** `reason:UrlACL`（响应里直接回显了本机出口 IP），`weather.cma.cn` 返回"WEB 应用防火墙…向右滑动填充拼图"。差一点把它们写成"站点不可用"或换成能打开的第三方域名。
原因：这类门户的 WAF 按来源 IP 段与请求特征拦截境外访问，测的是"本机到站点的链路"，不是服务本身的状态；用户从境内访问完全正常。
做法：状态码与拦截文案原样记进检索记录（含事件 ID 与 reason），条目改从 Wayback 原始快照取证；简介只写"对境外地址有访问拦截、国内网络访问更稳"这类可确认的条件，不换域名、不删条目，也不把拦截写成站点已死。

现象：Google Trends 与 Google News 用 urllib 抓回 39 万、38 万字节，去标签后仍有几十万字符，看着是"内容最充足的两条"，实际逐句检索不到任何第一方文案——整段都是样式表和脚本启动数据。
原因：单页应用把界面文案交给运行时渲染，静态 HTML 里塞的是构建产物；正文**长度**大与**取到可读句子**是两件事，之前只防了"正文太短"这一侧。
做法：判"取到文案"用能不能检索到一句带主谓的完整原话，而不是看字节数；几十万字节的应用壳按"未取到"处理，下一轮直接从浏览器读 `innerText` 开始。本轮确实没复读的条目，在检索记录里写明"只确认站点在线、简介维持功能描述"，不给它编条件与额度。

现象：想验证"没有弹窗的小栏目点开会显示什么"，用 `evaluate_script` 遍历十个页面的小标题逐个 `click()` 并读弹窗，调用直接超时；而这一轮真正需要的结论其实一行代码就能确定。
原因：`evaluate_script` 有约 15 秒的硬上限，跨多页、每页多次点击 + 读 DOM 的循环天然会超；同时把"界面实测"当成唯一取证方式，忽略了渲染分支可以从代码直接读出。
做法：批量界面操作按页面或栏目分片调用，一次只验一小段；判定"某状态在界面上长什么样"先读渲染函数确认分支（如集合缺失时走"无 / None"），再挑一个代表项实测，并在汇报里区分哪些是代码读出、哪些是浏览器实测。

现象：界面改成语言图标后，浏览器里点图标没反应、菜单是空的，控制台还一条报错都没有，看着像新代码写坏了。
原因：`index.html` 给样式表带了版本号（`styles.css?v=4`），脚本没带，浏览器一直在跑缓存里的旧 `app.js`；旧代码里的 `renderLanguages()` 往已经被删掉的 `#languageSelect` 上写内容，一执行就抛错，`init()` 中断，后面绑定点击的那段根本没跑到。
做法：先分清"是代码坏了还是浏览器在跑旧缓存"——对比服务器上的文件（`curl` 取 `/app.js` 找新函数名）和页面里实际执行的函数（`typeof 新函数`），不一致就是缓存，不用改代码。本项目**不给资源加版本号查询参数**（`styles.css?v=4` 这类写法已按用户要求删掉），验证时用地址栏加一次性参数（`/?_=时间戳`）或强制刷新绕开；一处出现缓存不一致，就把样式表和脚本都当"可能是旧的"来看，别只怀疑刚改的那一个。
